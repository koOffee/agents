# Codex engineering environment

Версионируемый набор правил для Python backend, CV/ML, аналитики и безопасной работы с удалёнными GPU-хостами. Репозиторий не содержит инфраструктурных адресов, ключей или строк подключения.

## Установка

На новой локальной машине клонируйте репозиторий, проверьте его содержимое и выполните:

```bash
bash scripts/install-local.sh
```

Скрипт создаёт ссылки на `skills/*` в `~/.codex/skills`. Он идемпотентен и останавливается, если на месте уже есть не принадлежащий этому клону файл; ничего не перезаписывает. После обновления клона skills обновляются автоматически через ссылки.

На удалённом сервере сначала подключитесь через свой заранее настроенный SSH alias, убедитесь в целевом каталоге и ревизии, затем клонируйте репозиторий и выполните в нём:

```bash
bash scripts/install-remote.sh
```

Скрипт намеренно не выполняет SSH, `sudo`, установку пакетов, запуск контейнеров или настройку MCP.

## Использование

- `AGENTS.md` задаёт общие правила и ссылается на предметные процедуры.
- Skills: `python-backend`, `computer-vision`, `analytics`, `remote-gpu`. Вызывайте нужный skill для задач соответствующего контура.
- Профили в `agents/` — versioned prompts для backend, CV, analytics и review. Подключайте их в настроенной у вас конфигурации subagents либо передавайте их содержание субагенту. Делегируйте только независимые, достаточно крупные части работы, которые действительно можно вести параллельно. `reviewer` полезен после существенных изменений, миграций и изменений доступа.
- MCP-настройки описаны в [mcp/README.md](mcp/README.md); добавляйте лишь необходимые read-only серверы локально.

## Что заполнить вручную

- SSH aliases, пользователя, порт, целевой каталог, допустимые GPU и команды контейнера/окружения.
- Команды запуска тестов, контейнеров и GPU-задач, если они отличаются от стандартных `uv`, `pytest`, Ruff и Pyright.
- Пути/URL MCP-серверов, имена переменных окружения и read-only роли PostgreSQL/ClickHouse.
- Токены, пароли, ключи и реальные строки подключения — только в защищённом локальном хранилище или переменных окружения, никогда в Git.

## Проверка репозитория

Для Markdown и TOML используйте любой доступный локальный валидатор. В этом шаблоне `pyproject.toml` уже задаёт Ruff и Pyright; его не меняли.
