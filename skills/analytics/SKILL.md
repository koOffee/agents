# Аналитика и SQL

## Безопасная процедура

1. Уточни цель метрики, гранулярность, временную зону, допустимую свежесть и источник истины.
2. Используй read-only подключение по умолчанию. Не выполняй `INSERT`, `UPDATE`, `DELETE`, DDL или production-запросы без явного разрешения.
3. До запуска на большой таблице ограничь период и объём, изучи схему и план выполнения.

## SQL и dbt

- Явно перечисляй поля, условия соединения и обработку `NULL`; не используй `SELECT *` в моделях и дашбордах.
- В PostgreSQL проверяй `EXPLAIN (ANALYZE, BUFFERS)` только с согласованными ресурсными пределами; оценивай индексы и кардинальность.
- В ClickHouse используй фильтрацию по ключу партиционирования/сортировки, избегай неограниченных сканов и тяжёлых `FINAL` без необходимости.
- Для dbt добавляй тесты `unique`, `not_null`, `relationships` и предметные проверки; проверяй `dbt build` для затронутого селектора.
- В Superset меняй только декларации/артефакты под контролем версий; не публикуй дашборды и не меняй источники без явного разрешения.

## Результат

- Укажи допущения, период, источники, SQL-план/оценку стоимости и ограничения результата.
- Добавь тест качества данных или воспроизводимый запрос для каждой новой критичной метрики.
