# Python backend

## Перед изменением

1. Прочитай маршруты, схемы, сервисы, модели, миграции и существующие тесты в затронутом контуре.
2. Определи контракт API, транзакционные границы, зависимости и стратегию ошибок.
3. Следуй `AGENTS.md` и настройкам `pyproject.toml`: `uv`, Ruff и строгий Pyright.

## Реализация

- В FastAPI отделяй HTTP-слой от бизнес-логики; валидируй вход и формируй явные Pydantic-схемы ответа.
- В SQLAlchemy не допускай N+1, не передавай невалидированные пользовательские данные в SQL и управляй жизненным циклом сессии явно.
- Для миграций добавляй обратимость, безопасные значения по умолчанию и план развёртывания. Не запускай миграции на production без явного разрешения.
- Для Ray фиксируй сериализуемые входы, лимиты ресурсов и поведение при повторе; не создавай вложенные задачи без необходимости.
- Фоновые задачи должны иметь идемпотентность, таймауты, наблюдаемое логирование и понятную стратегию повторов.

## Проверка

- Добавь или обнови API/интеграционные тесты на успешный сценарий, ошибку и границы данных.
- Для PostgreSQL проверяй миграцию на чистой и существующей схеме, если среда это позволяет.
- Выполни релевантные `pytest`, затем проверки из `AGENTS.md`; сообщи команды, которые не удалось запустить.
