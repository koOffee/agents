# Инженерные правила Codex

## Контекст и изменения

- До изменений изучи относящиеся к задаче код, документацию и текущий `git diff`.
- Делай небольшие, изолированные изменения; не переписывай рабочий код без причины.
- Уточняй цель, среду и риск, если этого нельзя надёжно вывести из репозитория. Не выдумывай хосты, команды, доступы и секреты.
- Используй `uv` для Python-зависимостей. На хосте работай в окружении проекта, в контейнере — в его штатном окружении; не устанавливай пакеты глобально.

## Качество Python

- Следуй существующей архитектуре и `pyproject.toml`: Python 3.12, Ruff (длина строки 88) и строгий Pyright для `src` и `tests`.
- Добавляй типы к публичным API; предпочитай `pathlib.Path`, встроенные generic-типы и точные типы вместо `Any`.
- Используй исключения для ошибок, логгер вместо `print()`, небольшие функции и Google-style docstrings там, где это улучшает понимание.
- Не ослабляй правила линтинга или типизации ради прохождения проверки: исправляй причину либо предложи исключение отдельно.

## Проверка

- После изменений выполни релевантные тесты, затем при возможности: `ruff format --check .`, `ruff check .`, `pyright` (если настроен), `pytest`.
- Не скрывай сбои: сообщи, какие проверки запускались и что осталось неразрешённым.

## Git и безопасность

- Не трогай несвязанные файлы, не сбрасывай пользовательские изменения и не делай коммит без прямой просьбы.
- Не добавляй в Git пароли, токены, ключи, строки подключения, внутренние адреса или дампы данных.
- Не выполняй разрушительные команды, DDL, запись в базы, production-операции, удалённые команды или изменения инфраструктуры без явного подтверждения и точной цели.

## Локальная и удалённая работа

- Перед работой на удалённой машине проверь пользователя, хост, каталог, ветку, доступные GPU/контейнеры и границы доступа. Пользуйся только явно настроенными SSH aliases.
- Сначала запускай безопасные проверки и локальные/изолированные тесты. Перед дорогими GPU-задачами, миграциями или широкими интеграционными тестами сообщи область воздействия и ожидаемые ресурсы.
- Для предметных процедур читай соответствующий skill в `skills/`.
